# SSH 项目默认锁死远端执行边界，仅经显式跨机互传交换文件

在「本机大脑 + 远程执行」架构下，本地 AI 同时具备操作本机与远程服务器的能力；如果放任常规工具同时访问双边环境，一句“清理输出目录”或“修改配置文件”极易误伤用户本机磁盘。我们决定在 SSH 项目会话内通过生命周期钩子强制隔离常规本地文件读写与命令执行（仅放行本机 Skill 说明与会话产物目录等安全路径），把代码与命令默认限定在目标 SSH 主机上，本机与远端之间的文件交换统一走显式的跨机互传通道。

## Considered Options

- **严格远端边界 + 显式跨机互传（已采纳）**：常规操作绝不误触本机，同时保留用户一句指令即可上传本地数据或下载远端产物的便利。
- **双边自由访问 + 提示词约束**：仅靠规则提醒 AI 优先操作服务器。模型长对话下存在跑偏风险，一旦误删或误改本机文件后果不可逆。
- **彻底禁止访问任何本机文件**：连跨机互传也不向 AI 暴露，所有文件传输强制手动完成。安全性最高，但破坏了“让 AI 帮我把本地数据传上去跑并把结果拉回来”的核心工作流。

## Consequences

- 远端命令的危险程度仍遵循 Antigravity 当前对话的原生权限配置，不叠加额外的硬编码高危拦截；防护重心放在“不跑错机器”。
- 未在项目能力范围内勾选的本机 Skill 激活与插件工具同样由边界钩子统一拦截，保证低侵入前提下的项目级隔离。
