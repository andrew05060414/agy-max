# 采用“本机大脑 + 远程执行”模式实现单窗口 SSH 项目

Antigravity 原生 OpenSSH 模式会在远端独立启动服务端、弹出单独窗口并要求重新完成账号授权，跨机切换和远端代理维护成本高。我们决定在 `agy-max` 中以「本机 AI 大脑 + 远端执行桥接」的方式实现 **SSH 项目**，将其作为云端形态的项目直接放进本地主窗口的左侧项目栏，并与原生 OpenSSH 窗口和平共处、不修改 Antigravity 客户端本体。

## Considered Options

- **本机大脑 + 远程执行（已采纳）**：账号授权、对话历史与插件能力全部留在本地桌面端，通过跨平台 SSH 执行通道访问远端文件、Git 与命令。彻底消除远端二次授权与独立窗口，且兼容无 Antigravity 服务端的旧 Linux 机器。
- **SSHFS / 本地挂载远程目录**：将远端目录映射为本地磁盘再配合远端执行命令。弱网和大仓库下读写卡顿明显，且强依赖各系统额外的虚拟文件系统驱动，破坏跨平台开箱即用。
- **隐藏并融合原生远端 Hub**：继续在远端运行 Antigravity 服务端，尝试通过窗口嵌合和自动同步登录态来掩盖切换过程。仍受限于远端环境兼容性、反向代理稳定性和账号授权边界，且侵入性过高。

## Consequences

- 本地主窗口同时拥有本地与远端执行能力，因此必须建立明确的远端执行边界，防止 AI 误操作本机文件。
- 聊天记录保留在本机，服务器关机或断网时仍可正常回看历史并在恢复后一键重连，也可直接更换 SSH 主机地址而保留完整项目对话。
- 所有本地项目体验（文件树、预览编辑、Git Diff、互传、终端等）需要通过远端执行通道提供对等实现。
